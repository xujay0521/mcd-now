# 下单与订单状态流程

## 订单确认卡

调用 `create-order` 前必须展示：

- 门店名称和 `storeCode`
- 到店自取及具体取餐方式
- 商品、数量、套餐选项和特调
- 使用的优惠券名称；不要展示完整 `couponCode`
- `calculate-price` 返回的最终应付金额
- 预约时间和餐具（适用时）
- 本次订单草稿的短指纹

只有“确认下单”“就按这个下单”等明确指令构成授权。“推荐一下”“算一下价格”
“这个不错”均不构成授权。确认只绑定当前草稿，任一字段变化后失效。

## 二次核价

1. 用户确认后，使用完全相同的门店、商品、券和履约参数重新调用
   `calculate-price`。
2. 用 `scripts/order_guard.py` 校验草稿并比较指纹。
3. 商品、数量、选项、券、门店、履约方式或价格变化时，展示差异并重新确认。
4. 未变化时使用核价返回的 `takeWayCode` 调用 `create-order`。

## 创建结果

- 成功时表述为“订单已创建，待支付”，返回官方支付链接或引导打开麦当劳 App。
- 不得把“订单已创建”表述成“支付成功”。
- 用户回复支付完成或支付失败后，调用 `query-order` 获取最新状态。
- `create-order` 超时或结果不明确且已返回订单号时，先调用 `query-order`。
- 结果不明确且没有订单号时停止，不直接重试；告知用户可能存在未知订单状态。

## 参数边界

- 到店自取：`orderType=1`、`beType=1`，不传 `beCode`，必传本次核价返回的
  `takeWayCode`。
- 预约下单必须传 `reservationDate`，非预约不得携带旧预约时间。
- 券必须成对传入 `couponId` 与 `couponCode`。
- 套餐和特调参数沿用本次核价成功的完整结构，不重新猜测或简化。

得来速和麦乐送属于后续版本。企业团餐不在本 Skill 范围内。

## 禁止场景

- `remind`、计划任务、cron、CI 和其他无人值守入口禁止下单。
- 用户未确认最终价格时禁止下单。
- 上次会话或上次核价的确认不能复用于新订单。
- 不因创建失败自动改用其他券、商品、门店或履约方式。
