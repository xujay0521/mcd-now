# 偏好模型

## 分类

| category | 内容 | 默认强度 |
|---|---|---|
| `restriction` | 忌口、过敏、明确禁用项 | hard |
| `favorite` | 偏爱的餐品或品类 | soft |
| `dislike` | 不喜欢但非安全约束的项目 | soft |
| `taste` | 辣度、酱料、冰量等口味 | soft |
| `meal_structure` | 单点、套餐、饮料和小食习惯 | soft |
| `budget` | 常用预算或价格倾向 | soft |
| `fulfillment` | 到店自取、常用门店及可接受距离 | soft |

## 写入规则

- “记住、以后、通常、一直”表示长期偏好，可以直接保存。
- “今天、这次、现在”只作为当前请求覆盖，不写入状态文件。
- 从历史订单或多次选择推断出的偏好必须先让用户确认。
- 保存过敏、宗教饮食等敏感约束前，复述内容并让用户确认。
- 用户可以查看、更新、删除单项或清空全部偏好。
- 首版不保存精确地址；常用门店只在用户明确要求时保存 `storeCode` 和门店名称。

## 持久化

- 状态使用带 `schema_version` 的 UTF-8 JSON，不依赖 SQLite。
- 相同类别和内容重复写入时返回已有项，不创建重复记录。
- 更新操作使用跨进程锁和原子替换，防止计划任务与对话同时写入造成丢失。
- 本次要求替换同类别长期软偏好，已保存的硬性限制始终保留。
- 内容相同的偏爱与反感、偏爱与限制会作为冲突报告，不静默选择一方。
- CLI 保存 `restriction` 时必须在用户核对后传入 `--confirm-sensitive`。

## 冲突处理

优先级从高到低：实时可售与券规则、硬性限制、本次要求、长期偏好、临期程度、
门店距离、价格。临期券与偏好冲突时，单独列为“快过期但不推荐”。
