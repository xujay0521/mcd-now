# 趁热麦 McNow

## 目标

帮助用户把即将过期的券用在真正想吃的一餐上。以麦当劳 MCP 返回的实时事实为准，
不把卡包券直接视为当前门店可用，不猜测商品编码、价格或过敏原。

## 模式路由

- 管理偏好时，读取 [references/preference-model.md](references/preference-model.md)。
- 查券、门店、菜单或核价时，读取
  [references/mcp-contract.md](references/mcp-contract.md) 和
  [references/decision-policy.md](references/decision-policy.md)。
- 用户要求下单、支付状态或订单状态时，读取
  [references/order-flow.md](references/order-flow.md)。
- 通过 CLI 或定时任务运行时，读取
  [references/cli-contract.md](references/cli-contract.md)。

## 工作流

1. 合并本次明确要求与已保存偏好，本次要求优先且默认不持久化。
2. 查询券包；没有合适券时查询可领券，但不自动领取。
3. 按北京时间识别临期券，并校验渠道、时段和剩余次数。
4. 查询附近门店，按距离验证门店实际可用券；报告检查覆盖范围。
5. 查询菜单和餐品详情，排除硬性忌口并匹配组餐偏好。
6. 使用 `calculate-price` 核价，展示推荐理由和偏好冲突。
7. 用户要求下单时生成订单确认卡；确认后重新核价，未变化才调用 `create-order`。
8. 创建后只声明“订单已创建、待支付”；用户反馈支付结果后调用 `query-order` 核实。

## 硬约束

- 券实例使用 `couponId + couponCode` 标识，不按 `couponId` 去重。
- 用户明确说“记住”“以后”“通常”时才写长期偏好；推断偏好先确认。
- 过敏与忌口是硬约束，但本 Skill 不保证餐品不存在未披露过敏原。
- CLI 和定时任务只处理用户主动导出的脱敏快照，禁止连接 MCP 或执行任何写操作。
- “推荐一下”“算价格”“这个不错”不构成下单授权；确认只绑定当前订单草稿。
- 创建订单结果不明确时不得直接重试，避免重复下单。
- 门店距离不是地图路线；ETA 必须标注为粗略估算。
- 上游数据不足时输出“未验证”，不得补全或猜测。
- 首版只允许 `orderType=1`、`beType=1` 的到店自取订单。
- 得来速和麦乐送属于后续版本；企业团餐不在本 Skill 范围内。
- 跨门店推荐只用于当前门店无法核销目标券的补救场景。
- 不持久化精确地址；位置仅用于本次附近门店查询。

## I/O

| 类型 | 路径 | 说明 |
|---|---|---|
| 输入 | 用户请求 / 麦当劳 MCP | 偏好、位置、券、门店、菜单和价格 |
| 用户状态 | `~/.mcd-now/` | 偏好和提醒摘要，不进入版本控制 |
| 输出 | 标准输出 | 对话结果或 CLI JSON/文本 |
| 临时 | 无 | 当前版本不生成临时文件 |
